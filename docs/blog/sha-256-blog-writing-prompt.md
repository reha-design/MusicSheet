# SHA-256 블로그 글 작성 프롬프트

아래 프롬프트를 복사해 사용하세요.

````text
당신은 정확하고 쉽게 설명하는 한국어 기술 블로그 작가입니다. SHA-256을 처음 접하는 일반 독자와 개발 입문자가 개념을 이해하고, 직접 파일의 해시를 확인할 수 있도록 블로그 글을 작성하세요.

## 작성 목표
- SHA-256이 무엇인지, 어떤 문제를 해결하는지 쉬운 말로 설명합니다.
- 파일 무결성 확인 예시를 들어 사용 이유를 보여줍니다. 예를 들어 테스트용 WAV 음원의 SHA-256을 기록해 두면 나중에 같은 파일인지 비교할 수 있다는 상황을 활용합니다.
- 독자가 SHA-256을 암호화, 비밀번호 복호화, 저작권 확인과 혼동하지 않도록 차이를 설명합니다.

## 꼭 다룰 내용
1. 해시 함수와 SHA-256의 의미
2. 입력 데이터가 달라도 해시 길이는 항상 256비트이며, 보통 16진수 64자리로 표시된다는 점
3. 같은 입력은 같은 결과를 만들고, 입력이 조금 달라지면 결과가 크게 달라지는 성질
4. 파일 무결성 확인 방법과 “해시가 같으면 같은 파일일 가능성이 매우 높다”는 실용적 해석. 충돌 가능성이 이론적으로 0은 아니라는 점도 짧게 설명합니다.
5. SHA-256은 암호화가 아니며 원래 내용을 해시만으로 되돌릴 수 없다는 점
6. 해시 비교만으로 파일을 만든 사람이나 출처가 진짜인지 증명할 수 없다는 한계. 신뢰할 수 있는 경로에서 받은 기준 해시와 비교해야 한다는 점
7. Windows PowerShell 예시:
   ```powershell
   Get-FileHash -Algorithm SHA256 "C:\경로\piano.wav"
   ```
   명령 결과에서 `Hash` 값을 확인한다고 설명합니다. Linux/macOS 예시는 필요할 때만 `sha256sum 파일명`으로 덧붙입니다.

## 구성과 문체
- 제목, 짧은 도입부, 소제목이 있는 본문, 명령 예시, 요약으로 구성합니다.
- 마지막에는 초보자가 기억할 핵심 3가지를 bullet로 정리합니다.
- 전문 용어는 처음 나올 때 풀어 쓰고, 지문 비유는 이해를 돕는 용도로만 사용합니다.
- 한국어로 자연스럽고 간결하게 씁니다. 과장, 불필요한 공포 조성, 근거 없는 보안 보장은 피합니다.
- 분량은 약 1,500~2,500자(공백 포함)를 목표로 합니다.

## 정확성과 출처
- SHA-256의 기술적 설명은 NIST의 Secure Hash Standard 자료를, PowerShell 명령 설명은 Microsoft 공식 문서를 확인해 근거를 둡니다.
- 웹 검색을 사용할 수 있다면 공식 문서를 우선 확인하고 링크를 인용합니다. 사용하지 않았다면 출처를 확인한 것처럼 꾸미거나 존재를 확인하지 않은 링크를 만들지 않습니다.
- 예시 해시 문자열을 넣을 경우 실제 파일에서 계산한 값이 아닌 설명용 예시라고 표시합니다. 실제 측정값인 것처럼 제시하지 않습니다.
- 초안을 마친 뒤 암호화와 해시를 혼동한 문장, “절대 충돌하지 않는다” 같은 과장, 출처로 증명되지 않는 주장이 없는지 자체 검토합니다.

완성된 블로그 글만 출력하고, 프롬프트에 대한 해설은 덧붙이지 마세요.
````
